# Deploy your private Auralis library

## 1. Create the Supabase project

1. Create an account at https://supabase.com and create a project on the Free plan in a region close to you. Save its database password in your password manager; the website does not need that password.
2. Open the SQL editor. Run `supabase/schema.sql` **once** in the new project. It creates the owner record table, library tables, private media bucket, and access policies. It intentionally fails instead of silently replacing existing tables or policies.
3. In Authentication settings, **disable new user signups** and anonymous sign-ins. Keep email/password authentication available. Configure Auth rate limits and enable supported CAPTCHA protection for sign-in if adding a CAPTCHA widget in a subsequent hardening step. This version relies on Supabase's Auth rate limits and mandatory MFA; it does not include a CAPTCHA widget.
4. In Authentication → Users, create your sole account with a unique password generated by a password manager (at least 20 characters recommended). Confirm the email through the admin interface if required. Do not reuse your Supabase dashboard password.
5. Copy that user's UUID and run the following in the SQL editor, replacing the placeholder:

   ```sql
   insert into public.app_owner (user_id) values ('YOUR-USER-UUID');
   ```

   The table permits only one owner. The browser cannot create, change, or delete ownership.
6. Keep TOTP MFA enabled in Auth settings. On your first Auralis sign-in, scan the displayed QR using an authenticator and verify its six-digit code. Files remain inaccessible before MFA verification. Store an encrypted authenticator backup securely; do not send the QR or backup to anyone.
7. Obtain the **Project URL** and **public publishable key** (or legacy anon key) from the project's Connect/API settings. These two values are intentionally public. **Never use the secret/service-role key.**
8. Verify Storage → `media` is **private**, its size limit is 50 MB, its MIME allowlist matches the migration, and there are no additional permissive storage policies from other projects/templates. Use a dedicated project for this app.

## 2. Deploy on Vercel

1. Create a Vercel account and connect your GitHub account. Import `powervoltinnovations-web/auralis`.
2. Choose Next.js, repository root, Node.js 22 or newer, `npm run build`, and the default output directory.
3. Set the production branch to `main`.
4. Add these variables in Vercel for Production (and Preview only if you want it connected to the same private library):

   ```text
   NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLIC_PUBLISHABLE_OR_ANON_KEY
   ```

   Do not configure a service-role key. Deploy/redeploy after changing these build-time public variables.
5. Deploy. Vercel supplies your HTTPS public address. Missing or partial project variables show a configuration message instead of silently opening a preview. Do not enable `NEXT_PUBLIC_ENABLE_LOCAL_PREVIEW` in your real deployment; this switch is for explicit preview/test builds only.
6. Put the exact deployed HTTPS origin in Supabase Auth's Site URL. Do not add broad wildcard redirect URLs. This app uses password/MFA login and does not process authentication tokens in the URL.
7. Keep Vercel's available DDoS/firewall protections enabled. Enable MFA on your Vercel, GitHub and Supabase accounts as well.

## 3. Verify before using personal files

- In a private/incognito window, confirm the production app shows sign-in.
- Confirm that public account registration is disabled in Supabase.
- Sign in as owner; confirm the library is blocked until authenticator verification.
- Upload a small MP3 or compatible MP4, then sign in on your iPhone and play/seek it using mobile data.
- Run the cloud checks in `SECURITY.md`. Test unverified owner and non-owner access using isolated test sessions. Remove the temporary non-owner account afterward.
- Verify private bucket downloads fail without authorization; validate short-lived link expiry.
- Confirm signing out clears the displayed library and playback. A previously issued playback link can remain usable until its expiry.
- Check HTTPS and the security headers. Do not make the bucket public to fix a playback error.

## Hosting limits and recovery

Official current plan details: https://vercel.com/pricing and https://supabase.com/pricing . Review those before enabling billing. Vercel Hobby is intended for personal/non-commercial use under its current terms. Free Supabase projects can have storage/egress limits and inactivity pauses. The app does not monitor your billing quota or guarantee a free service indefinitely.

Files upload directly to Supabase, avoiding Vercel request-body limits. Uploads are standard uploads rather than resumable uploads; keep the uploading browser open and use a reliable connection. The app shows the file currently being transferred, not a byte-level percentage.

Keep original copies of your media; this app is not a backup service. If the authenticator is lost, recover through the Supabase project administrator using its supported MFA recovery controls. Do not weaken the database policies or add a recovery backdoor. Protect dashboard credentials with MFA.

## ZIP delivery

The source ZIP includes application source, dependency lockfile, SQL and documentation. It excludes `.git`, `.env.local`, dependencies, build output, media and credentials. Extract, run `npm ci`, configure the project as above, then deploy. No account password is delivered inside the ZIP.
